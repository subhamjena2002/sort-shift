# SORT SHIFT art pipeline

All game art is generated by the Python scripts here. Nothing is modelled by
hand, so every asset can be rebuilt from this folder.

## Requirements

- Blender 5.2 (the assets were made with 5.2.3 LTS). No add-ons or paid assets.
- A separate Python 3 with Pillow and NumPy, for the final conversion step.

## Regenerating the assets

From the repository root:

```bash
"C:/Program Files/Blender Foundation/Blender 5.2/blender.exe" --background --python blender/scripts/render_assets.py -- all
```

```bash
python blender/scripts/build_web_assets.py
```

The first command renders into `blender/source/` and saves editable scenes in
`blender/projects/`. It takes about four minutes on an Iris Xe laptop. Pass any
of `parcels`, `conveyor`, `bins` or `backgrounds` instead of `all` to render one
group. The second command writes the WebP files to
`public/assets/images/blender/` and refreshes `blender/previews/`.

Always inspect `blender/previews/asset_contact_sheet.png` afterwards.

## Scripts

| Script | Purpose |
|---|---|
| `create_asset_studio.py` | Shared camera, lights, materials, mesh builders and checked rendering |
| `generate_parcels.py` | Eight parcels and the golden carrier |
| `generate_conveyor.py` | Seamless belt and rail tiles, roller hub |
| `generate_sorting_bins.py` | Left and right bins |
| `generate_factory_background.py` | Separate landscape and portrait factories |
| `render_assets.py` | Blender entry point that runs the generators |
| `build_web_assets.py` | Shadow composition, WebP output, contact sheet and size report |

## Decisions worth knowing

- **Golden parcels.** `golden_bonus` is a gold carrier with a frame and star,
  drawn underneath the real parcel. Golden parcels are still sorted by colour or
  shape, so that parcel has to stay visible.
- **No sorting text in the art.** Parcels have a blank label plate. Phaser draws
  the colour name and symbol at runtime, so they stay readable and accessible.
- **Contact shadows.** Eevee has no shadow catcher, so each sprite is also
  rendered on a white floor with and without the object. The difference between
  those two renders becomes the sprite's soft shadow.
- **Light-loss protection.** With shadows on, Eevee sometimes renders as if all
  lamps were off (seen on Iris Xe in background mode, with every shadow setting
  tried). `render_to` first makes a stable render without shadows, repeats the
  real render until it reaches that light level, and rebuilds the scene if it
  never does. A successful run logs `light=` close to 1 for every image.
- **Ray tracing is off.** It left coloured noise on dark metal.
- **Standard view transform.** AgX washed out the parcel colours.
- **Tiles.** Belt and rail use directional lights only, and each repeating part
  is modelled one period beyond the frame, so the edges wrap. The size report
  records the seam difference for both.

## Changing how art lines up in the game

`src/game/assets/assetManifest.ts` holds the manifest and the measurements that
align art with the game (`PARCEL_ART`, `BIN_ART`). If a camera framing or model
proportion changes here, update those values to match.
